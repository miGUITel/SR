## Zonas DNS: cómo se responde a una consulta

Hay que separar el servidor que tiene autoridad para una zona del servidor que resuelve consultas para sus clientes. Un mismo equipo puede desempeñar ambas funciones.

### Datos autoritativos y caché

- Si el servidor tiene autoridad para la zona consultada, responde con los datos de esa zona. Puede ser primario o secundario.
- La respuesta autoritativa también puede indicar que el nombre no existe o que no tiene registros del tipo solicitado.
- Si necesita resolver otros nombres y ofrece recursión, puede usar datos de su caché, reenviar la consulta o recorrer la jerarquía. La configuración determina qué hace.

**No existe un orden universal «zona primaria, zona secundaria, caché».** Primario y secundario son funciones por zona, no niveles sucesivos de búsqueda. La zona secundaria contiene una copia autoritativa y puede responder sin preguntar primero al primario.

La caché guarda respuestas durante un tiempo limitado por el TTL. También se pueden almacenar respuestas negativas.

### Consulta desde el cliente

La aplicación pide resolver un nombre. El sistema puede consultar fuentes locales como `hosts` y la caché del cliente, y enviar una consulta al DNS configurado cuando corresponda.

El orden de las fuentes depende del sistema, de su configuración y de la aplicación. En Linux interviene, entre otros elementos, la configuración de resolución de nombres del sistema. En Windows, la caché del cliente puede contener entradas precargadas desde `hosts`. No hay una secuencia idéntica para todos los equipos.

La caché del cliente, la del navegador y la del servidor DNS son distintas. Vaciar una de ellas no vacía las demás.

### Proceso de Resolución DNS desde el Cliente:

Ejemplo habitual, sin fijar un orden universal:

1. La aplicación solicita un nombre al resolvedor del sistema.
2. Si las fuentes locales permiten resolverlo, el sistema devuelve el resultado.
3. Si necesita DNS, el cliente consulta a su servidor configurado, normalmente solicitando recursión.
4. El servidor responde con sus datos, su caché o información obtenida de otros DNS, según su función y configuración.
5. La aplicación recibe el resultado o un error.

Si el servidor debe recorrer la jerarquía pública, el propio resolvedor sigue las referencias de raíz, TLD y servidores autoritativos. El cliente ordinario no tiene que hacer personalmente ese recorrido.

`nslookup` consulta DNS directamente. Su respuesta no permite comprobar una modificación de `hosts` ni demostrar el uso de la caché del cliente.
